## Mission and primitive classes

Produce only a literal lightweight Researcher Inventory candidate from the supplied source.

Primitive classes are exactly:

1. `PLACE`
2. `TIME`
3. `PERSON`
4. `OBJECT`
5. `LABEL`
6. `VERB`
7. `LOCATOR`

The inventory is richer than a sparse summary and narrower than a lexical, grammatical, dependency, event, assertion, or proposition census.

## 1. Stable source-packet map

For every request on the same source, reconstruct or maintain the same internal source-packet map before deciding the requested class. The requested class selects only what you return; it must not change what situations, relations, frames, participants, referents, characterizations, positions, or orientations the source itself stages.

A **source-staged research packet** is a bounded represented situation, relation, characterization, site/position, or organizing frame whose research identity would materially change if one of its source-staged participants, referents, relation, characterization, site/frame, or orientation changed.

Packets are source-grounded, not analyst-created summaries. They may be broad or local and may nest when both levels organize material. A sentence may contain zero, one, or several packets. Several sentences may contribute to one packet. Do not create one packet for every clause, predicate, dependency, noun phrase, or prepositional phrase.

A packet may include reported, remembered, prospective, hypothetical, uncertain, corrected, negative, questioned, or present-reflection material without asserting that material as fact.

## 2. Mandatory construction order — source anchor, then class gate

1. Read the complete source once without returning primitives.
2. Resolve strict coreference, source order, scene/episode shifts, reported/remembered/prospective posture, uncertainty, negation, correction, and materially distinct represented situations.
3. Build the bounded source-packet map in source order. Keep it literal: identify source-staged slots/relations, not analyst category names.
4. For the requested primitive class, run **Pass A — source-order discovery** across every packet and shared structural frame/site. Candidate discovery starts from exact source wording/cues or lawful unnamed PLACE/TIME coordinates.
5. Apply the universal retain/remove gate in Section 3 to every Pass A candidate.
6. Run **Pass B — class-order structural coverage** across the complete source, asking only whether a class-native source-staged slot was missed by Pass A. This pass is for recall, not for lexical census.
7. Apply the identical retain/remove gate to Pass B candidates. Do not use a looser rule merely because the item was found during coverage.
8. Merge only true same-class identity/coreference/repetition. Preserve genuinely distinct roles even when associated, co-located, nested, or expressed with similar wording.
9. Apply the structural-floor audit and anti-census ceiling audit.
10. Apply literal/posture lock and freeze primitive membership.
11. Build compounds only from frozen primitives by replaying minimal retained source-staged research packets.
12. Run final typing, lexical, packet, compound, and isolation audits.

Do not begin from a compressed conceptual summary. Do not begin from seven exhaustive lexical lists. Do not begin from an exhaustive proposition ledger.

## 3. Universal retain/remove gate

A primitive survives only when all applicable parts of this gate pass.

### 3.1 Source grounding

The source itself must stage the candidate. Use an exact source-native atom, except lawful unnamed PLACE/TIME coordinates may use null `source_wording` anchored by an exact source cue.

Reject analyst-created category names, proposition labels, diagnoses, normalized concepts, explanatory paraphrases, conventional substitutions, noncontiguous composites, or semantic completions.

### 3.2 Class-native function

The candidate must perform the requested class's function in at least one retained packet or as a structural site/frame shared by retained packets. Surface form never decides the class.

### 3.3 Packet necessity

Ask: **If this candidate disappeared while the rest of the packet stayed fixed, would a distinct source-staged participant/referent/characterization/relation/site/frame/orientation slot be lost or materially blurred?**

If yes, the candidate may survive even when brief, generic, deictic, one-use, low-salience, or context-dependent.

If no, and the candidate exists only because a token, phrase, grammatical relation, or parseable proposition is present, remove it.

This is not an importance test. A mundane or tiny source-staged slot can be retained. It is also not a clause-completeness test. A semantically rich clause does not automatically create an inventory primitive.

### 3.4 Minimal source grain

Use the smallest exact contiguous span that preserves the source-native identity of the retained function.

Do not attach actor/object/place/time arguments merely to make a relation or characterization self-explanatory. Do not widen a deictic or generic atom so it reads well outside context.

Widen only when removing material would change the identity of the source-native unit, such as an identity-bearing particle, negation, modal/control material, idiomatic complement, coordinated relation, or contrast.

### 3.5 Same-class distinctness

Merge only true same-class same-identity coreference/repetition. Association, co-location, part/whole, container/content, actor/role, broad/local frame, shared topic, semantic similarity, or participation in the same packet is not identity.

### 3.6 What never creates a primitive by itself

None of these is sufficient:

- a token or phrase exists;
- a noun/adjective/verb/preposition/adverb is present;
- a sentence or clause says something;
- a proposition or event can be reconstructed;
- a dependency parser would isolate a relation;
- wording looks spatial, temporal, descriptive, relational, or referential;
- a phrase can be nominalized;
- a local predicate has participants;
- a modifier changes local meaning;
- a prepositional phrase has orientation semantics;
- an item is vivid, important, or useful for summary;
- an item is materially true of one sentence.

The positive reason must be a distinct source-staged class-native slot in a retained packet or shared structural frame/site.

## 4. Two-pass coverage without census

### Pass A — source-order discovery

Replay every retained packet in source order. For the requested class, capture each distinct source-staged class-native slot before considering whether the wording seems important, elegant, self-contained, or frequent.

### Pass B — class-order structural coverage

Replay the entire source solely for the requested class and ask what Pass A could have missed because it was brief, deictic, unnamed, low-salience, one-use, nested, possessive, reported, remembered, prospective, uncertain, negative, corrected, questioned, figurative, or context-dependent.

Pass B may add only candidates that pass the same universal gate. It may not turn class-looking vocabulary into rows.

The purpose of two passes is convergence: source order protects literal/local coverage; class order protects structural recall. Neither pass overrides the anti-census ceiling.

## 5. Cross-class multiplicity and non-substitution

Type by represented source function, never by part of speech.

The same exact source span may lawfully appear in more than one primitive class when it performs genuinely different retained functions in the source-packet map. Exact textual overlap is not itself duplication across classes.

Do not create cross-class twins merely because grammar permits multiple descriptions. Require a real functional difference.

No retained class absorbs a different retained function: OBJECT does not absorb LABEL; LABEL does not absorb VERB; PLACE/TIME do not absorb LOCATOR; VERB does not absorb actor/object/site/frame; LOCATOR does not replace PLACE.

## 6. PLACE — represented sites and positions

`PLACE` inventories distinct source-staged physical/institutional settings and represented occurrence, participant, or referent positions that ground retained packets.

Retain PLACE when the source stages **where** a packet, participant, referent, or represented occurrence is positioned and removing that position would blur a distinct packet slot.

Rules:

- Physical naming is not required.
- Lawful unnamed positions are allowed when an exact source cue stages the position.
- Broad and contained sites may both survive when each grounds distinct packet structure.
- Co-located participants/occurrences may have separate unnamed positions when the source stages them as distinct positional roles.
- Reported, remembered, prospective, or present-telling material may have its own represented position when source structure requires it.
- A physical noun, surface, container, body part, direction, movement phrase, distance word, or spatial-looking expression is not PLACE merely because it can be located.
- Do not create a PLACE for every action simply because every action occurs somewhere.

For lawful unnamed PLACE use `source_wording = null`, an exact source cue, and neutral mechanical wording. Never invent a more specific location than the source supports.

## 7. TIME — organizing frames and phases

`TIME` inventories distinct source-staged episodes, periods, phases, attempts, waits, interactions, transitions, recurrence spans, remembered/reported/prospective frames, and present telling/reflection frames that organize retained packets.

Retain TIME when a frame groups, positions, separates, nests, or transitions retained packets/material. A short event may be TIME when the source uses it as a frame or phase boundary, not merely because the event happened.

Rules:

- No date, clock, duration, frequency word, tense, or temporal noun is required.
- Broad and nested frames may both survive when each organizes material at a distinct level.
- Waiting, interaction, recurrence, intended, remembered, reported, prospective, transition, and present-reflection frames may qualify.
- Explicit temporal wording is not automatically TIME.
- Do not make every action, clause, verb, tense/aspect shift, discourse transition, or local moment into TIME.

For lawful unnamed TIME use `source_wording = null`, an exact source cue, and neutral mechanical wording.

## 8. PERSON — stable represented actors and social endpoints

`PERSON` inventories `B` plus every distinct stable represented human or social actor/group after strict coreference when the source gives that actor/group its own slot in a retained packet.

Participation includes acting, speaking, perceiving, being acted upon, possessing, receiving, benefiting, accompanying, being a relational endpoint, being the source/target of a relation, or otherwise being materially implicated in a retained packet. Do not require speech or action. A minor, offscreen, possessively introduced, beneficiary, relational, institutional, or group actor may qualify when source-established and distinct.

Exclude rhetorical/generic addressees, generic hypothetical roles, pronouns with no stable referent, and true aliases/coreference duplicates.

Order non-speakers by first independent represented participation rather than incidental mention alone.

## 9. OBJECT — source-treated things and content referents

`OBJECT` inventories source-established things and content referents that occupy distinct slots in retained packets.

Lawful OBJECTs may include physical things, scene items, products, documents, parts, surfaces, containers, amounts/values, sets, choices, decisions, plans, relationships-as-content, recurring situations, conditions, services, results, mental contents, comparison vehicles, and explicitly reified relations.

Retain a low-salience or one-use referent when the source actually treats it as something handled, positioned, possessed, selected, compared, evaluated, noticed, remembered, decided, questioned, appraised, pointed back to, or used as a relation endpoint in a retained packet.

Use the source's smallest referential atom. Do not create:

- a proposition shell merely because a sentence expresses content;
- an analyst-completed “thing” from a clause;
- a conceptual summary of what someone wanted/meant/decided unless the source itself treats that content as a referent;
- every noun phrase merely because it can fill an argument slot;
- a setting duplicated as OBJECT when its only retained function is PLACE;
- an unstable pronoun/demonstrative as a separate object when strict coreference resolves it to an already retained object.

## 10. LABEL — source-applied characterization, status, manner, and polarity

`LABEL` inventories source-applied states, qualities, statuses, identities, classifications, evaluations, comparisons, manners, polarities, corrections, rejections, intensifications, and characterization questions when the source gives that characterization its own slot in a retained packet.

LABEL is functional, not part-of-speech based. A retained label may be adjectival, nominal, adverbial, deictic, comparative, idiomatic, fragmentary, questioned, negative, or context-dependent.

Retain the smallest exact source-native atom that performs the characterization/status/polarity function. Preserve uncertainty, question, negation, rejection, correction, contrast, attribution, colloquial wording, and material intensity.

Do not create LABEL from every adjective, adverb, modifier, colorful phrase, rhetorical flourish, or local descriptive fact. The characterization must be source-staged as a distinct packet slot rather than merely syntactic decoration.

## 11. VERB — source-native relation atoms

`VERB` inventories the smallest exact source-native lexical relation atoms that perform distinct relation functions inside retained packets.

A VERB qualifies when removing that relation would erase or materially blur how retained participants/referents/sites/frames/characterizations are connected or what state/transition/action/perception/cognition/report/intention/possession/movement/wait/support/copular relation the packet stages.

Do not require a relation to look semantically important or self-contained. Short, generic, support, copular, reporting, cognition, movement, waiting, state, modal, and context-dependent relations may qualify when they carry a distinct retained packet relation. Conversely, a vivid or content-bearing predicate does not qualify merely because it has semantic content.

Use the smallest exact contiguous lexical kernel that preserves relation identity. Keep particles, directionals, reflexives, negation-bearing material, modal/control/infinitival material, idiomatic complements, or coordination only when necessary to preserve that identity.

Do not:

- harvest every grammatical predicate;
- keep auxiliary material that contributes no distinct relation;
- keep repeated/coreferential relation wording as separate same-class identities;
- attach arguments merely to make the relation readable;
- merge distinct retained relation atoms merely because they share a clause;
- suppress a retained relation merely because its wording is generic, brief, deictic, or context-dependent.

Matrix/embedded or coordinated relations may split when the source stages materially distinct packet relations and remain together when they form one source-native relation identity.

## 12. LOCATOR — source-native orientation and contextual relation atoms

`LOCATOR` inventories exact source-native orientation/context relations that materially situate a retained packet or one of its coordinates.

Eligible functions may include relative position, containment, direction, path, origin/destination, entry/exit, approach/departure, proximity/distance, accompaniment/carrying, recurrence/situational context, embodied/internal orientation, source/target orientation, and materially useful figurative/comparison orientation.

LOCATOR is functional, not part-of-speech based. A locator may be a prepositional phrase, adverbial/deictic atom, relation fragment, verb-like phrase, temporal/situational context phrase, or figurative orientation when that exact source atom performs the retained orientation job.

Ask: **If this exact orientation/context atom disappeared, would the retained packet lose a distinct answer to how/where/from/to/through/with/relative-to/within-what-context a coordinate or relation is situated?** If yes, it may qualify even when brief or context-dependent.

Use the smallest exact local span that carries the retained orientation function. Do not merge neighboring atoms merely to make one self-contained phrase.

Suppress bare grammatical prepositions, routine recipient/topic marking, possession alone, incidental adverbials, and local context phrases when they do not occupy a distinct packet-orientation slot.

## 13. Literal, contiguity, and posture lock

Every source-derived non-null string must preserve source language character-for-character wherever the schema requires source text.

Never synonymize, lemmatize, repair spelling/grammar, normalize dialect, expand contractions, translate, polish, diagnose, standardize a group/category name, change number, or substitute a conventional expression. Do not replace source-native labels for people/groups/things with analyst-created category names.

Do not concatenate noncontiguous fragments into one primitive. Do not silently add omitted words. Do not broaden a fragment merely so a reader can understand it without context.

`source_wording`, `source_cue`, and `order_cue` must be exact source text where applicable. Only genuinely unnamed PLACE/TIME may use null `source_wording`.

Questions, uncertainty, hypotheticals, negations, self-corrections, remembered possibilities, reported material, and proposed future actions remain in source posture. Inventorying does not assert truth or realization.

## 14. `qualities_available`

`qualities_available` is a mechanical boolean only. True means the source supplies material qualities/descriptions associated with the coordinate; false otherwise. Do not create or split primitives to justify the boolean. `Q` is never a primitive.

## 15. Ordering

Default within-class order is first material source anchor after filtering/coreference.

Tie rules:

- broad/whole setting before dependent/contained setting when introduced together;
- whole before dependent part at the same anchor unless the source stages the part first;
- PERSON follows first independent represented participation;
- remembered/reported/hypothetical/future frames remain at source position rather than external chronology.

The apparatus owns canonical IDs and deterministic numbering.

## 16. Structural-floor audit — recover source-staged omissions

After Pass A and Pass B, replay every retained packet and the whole source. Check whether any distinct class-native slot disappeared merely because it was brief, generic, unnamed, deictic, context-dependent, low-salience, nested, one-use, possessively introduced, reported, remembered, prospective, uncertain, negative, corrected, questioned, or figurative.

Check especially for:

- unnamed participant/referent/occurrence positions that genuinely ground a retained packet;
- broad/local frames, waits, interactions, transitions, recurrence, remembered/reported/prospective frames, and present-reflection frames that organize packet structure;
- minor actors/groups/endpoints with genuine packet participation, including beneficiary/possessive/relational participation;
- low-salience concrete or abstract referents explicitly used as packet coordinates;
- source-applied characterization/polarity/status/manner atoms that materially qualify a packet coordinate;
- short/generic source-native relations whose loss would erase a packet relation;
- short/deictic/figurative/context orientation atoms whose loss would erase packet orientation;
- lawful same-span cross-class functions.

Add a missing primitive only when it passes the universal gate. Never widen or retype a neighbor to compensate.

## 17. Anti-census ceiling audit — remove lexical/grammatical leakage

For every retained primitive ask:

1. Which retained source-staged packet or shared structural site/frame contains this function?
2. What exact class-native slot does it fill?
3. If removed, what distinct packet slot/relation/orientation would be lost or materially blurred?
4. What exact source span/cue grounds it?
5. Is this the smallest exact contiguous span preserving identity?
6. Did grammar, part of speech, lexical vividness, a parseable proposition, or summary usefulness create the item instead of merely realizing a source-staged slot?
7. Did I invent, normalize, complete, merge, paraphrase, or widen it?
8. Is it truly distinct from same-class identity/coreference/repetition?

If questions 1-3 do not have a source-grounded answer, remove the primitive even when the phrase is meaningful or easy to classify.

Never aim for a hidden row count or density.

## 18. Compound construction — minimal packet replay

Freeze primitives before compound work.

A compound represents one minimal **retained source-staged research packet** among two or more frozen primitives. It reconnects the packet; it does not create the packet or repair primitives.

Create a compound when:

1. the source stages a distinct relation/characterization/position/frame connection among at least two frozen primitives;
2. the connection is one of the retained packet relationships rather than merely a grammatical dependency;
3. the compound includes the frozen primitives active in that minimal packet and excludes inactive neighbors; and
4. the result is not an alternate parse, pairwise/transitive closure, one-compound-per-token artifact, automatic one-compound-per-clause artifact, duplicate/subset alias, or scene-wide mega-bundle.

A packet with several materially distinct source-staged relations may yield several minimal compounds. Several clauses that express one retained packet need not yield several compounds.

VERB, LABEL, and LOCATOR participate when active in the packet. PLACE/TIME participate when they actually position or organize that packet. Do not omit a relevant frozen structural coordinate merely because its wording is unnamed or low-salience.

A compound cannot create, delete, merge, retype, or substitute for a primitive. If a required packet slot is missing, primitive selection failed and must be corrected before compounds.

Canonical compound IDs/order and `_Q` construction remain apparatus-owned.

## 19. Final contrast audit

### Too dense / census failure

Warning signs:

- candidates are generated from all tokens/phrases before packet structure;
- every grammatical predicate becomes VERB;
- every noun phrase becomes OBJECT;
- every description/modifier becomes LABEL;
- every local moment or temporal word becomes TIME;
- every spatial/context phrase becomes PLACE/LOCATOR;
- every represented assertion becomes a packet;
- compounds track nearly every clause.

Correct by returning to the bounded source-packet map and universal gate.

### Too sparse / abstraction failure

Warning signs:

- a source-staged slot is omitted because it seems unimportant, generic, context-dependent, or too small;
- an unnamed site/frame disappears because it lacks a source noun;
- a minor actor/group disappears because it does not act or speak;
- a tiny relation/orientation atom is dropped because it is not self-contained;
- several source-staged slots are replaced by one conceptual summary;
- source wording is replaced by analyst terminology;
- the class request causes the source-packet map to change.

Correct by returning to exact source anchors/cues and re-running both passes under the same gate.

## 20. Final audit

Before return verify:

- **Stable packets:** the same bounded source-packet map governed this source regardless of requested class.
- **Source-order recall:** Pass A inspected every retained packet in source order.
- **Class-order recall:** Pass B checked the entire source for omitted class-native slots.
- **One gate:** every retained item passed the same source/function/packet-necessity/minimality/distinctness gate.
- **Structural floor:** low-salience/unnamed/deictic/context-dependent source-staged slots were not suppressed for lack of salience or self-containment.
- **Census ceiling:** no primitive exists merely because a grammatical or lexical item can be classified.
- **Source atomicity:** every non-null primitive uses the smallest exact contiguous source-native span preserving identity.
- **Typing:** every primitive is typed by represented source function.
- **Cross-class:** genuine different functions may share wording; alternate parses do not multiply rows.
- **Literal/posture:** exact wording, dialect, polarity, question, uncertainty, negation, and posture are preserved.
- **Compounds:** only minimal retained source-staged packet relationships reassemble frozen active refs.
- **Candidate:** no promotion, scoring, APA identity, or database action occurred.
